# Git 项目工作流

项目文件区现在同时包含 **代码仓库** 与 **项目资料**。代码仓库使用真实 Git；已有共享文档、附件及其 SQLite 文件版本仍独立保存，二者不会自动相互覆盖或上传。

## 使用流程

1. 项目主人关联一个 HTTPS / SSH 仓库地址与目标分支（默认 `main`）。仓库已有工作区时，需先断开它们才能更换地址或目标分支。
2. 每位成员选择自己的 AI、可选的已批准任务，以及“连接已有仓库”或“克隆到新目录”。本机路径只用于生成提示词，不存入 CoNest。
3. 勾选本地提交/同步权限，以及独立的推送权限。两者默认关闭。复制接入提示词给自己的本地客户端。客户端需具备 CoNest 源码、安装好的依赖、Node.js 24+、Git 和现有 AI 连接配置 `connection.json`；当前面向 macOS / Linux，此版本不会从网页远程安装本地软件。
4. 客户端通过 JSON stdin 运行 `npm run --silent git -- pair`。它读取现有连接配置，在本机生成另一个独立的 runner 凭证，只发送其哈希。网页与本机都显示相同的八位设备指纹；主人核对并批准后才允许准备仓库或领取任务。
5. 执行器在选择的仓库旁创建 `<仓库目录>.conest-<工作区ID>` worktree，从 `origin/<目标分支>` 创建固定的 `conest/task-<任务ID前8位>-<工作区ID前8位>` 或 `conest/workspace-<工作区ID前8位>` 分支。原工作目录的未提交改动保留原处；它们不会被自动复制到新目录。已存在的克隆目的目录会被拒绝。
6. 打开项目文件后自动读取在线工作区状态。可以预览仓库文件、查看差异和最近二十条提交，勾选修改文件并填写说明，提交到本地。文件清单当前最多显示 500 条，文本预览最多 64 KB；大文件、子模块、符号链接及敏感路径需在本机另行处理。
7. 工作目录干净且获准推送时，“提交审核”会展示发布说明。确认后推送固定工作分支，并共享分支名、commit SHA、任务与审核入口。关联任务进入 `review`，不会自动进入 `done`。
8. GitHub / GitLab.com 提供打开创建 PR/MR 页面的链接，**当前不直接调用托管平台 API 创建 PR/MR，也不自动合并或读取审核结果**。其他 Git 托管服务显示手动创建审核请求的提示。

CoNest 项目成员身份不会赋予 Git 托管平台的仓库权限。克隆与推送使用运行机器已有的 Git 凭证管理器 / SSH agent；没有登录时操作失败，凭证不会被 CoNest 代为收集或写入提示词。

## 本地运行

接入成功后，程序在 stderr 报告实际 worktree 与 `git.json` 路径并保持运行。停止用 Ctrl+C / SIGTERM。重启：

```sh
npm run --silent git -- run --config /absolute/path/git.json
```

`git.json`、AI token 文件和 runner token 文件均需当前用户所有、权限 0600，并放在仓库与 worktree 外。执行器重新读取本地授权；关闭本地 `allowWrite` / `allowPush` 后，后续相关操作会被拒绝。改变连接身份、目录、分支或远程地址需要重新接入。原生客户端文件编辑授权仍单独配置；Git runner 不提供文件写入或任意终端工具。

独立私人/任务会话可以挂载本地 stdio MCP：

```sh
npm run --silent git -- mcp --config /absolute/path/git.json
```

提供 `get_git_workspace` 和 `git_operation`。后者只接受 `status / files / read / diff / log / commit / sync / push` 的结构化参数，通过同一个 runner 队列执行。Commit 需要明确的 `paths`、`message` 和最近 `status.version`；Push / Sync 也需要 `expectedVersion`。不提供任意命令字符串、删除分支、强推、reset、clean、自动解决冲突或合并工具。

**不要把这个 MCP 挂载到伙伴提问、会议点名或其他处理外部请求的自动回复会话。**远程 CoNest MCP 不增加本地 Git 工具。设备凭证只存在于本机，普通 AI token 本身不能代替该凭证或主人的连接批准。

## 执行与权限边界

- CoNest 服务端只保存仓库关联、授权、操作队列和审核元数据，不运行 Git，也不访问成员磁盘。本机执行器主动发起请求，每两秒领取操作，不开放本机网络监听端口。超过三十秒未心跳显示离线。
- 操作结果及文件/差异预览会发送到 CoNest，以便网页展示，只允许工作区主人读取。每个工作区保留约二十条最近完成记录；运行中记录另保留，下一次入队时清理旧结果。它们会进入数据库备份；不是端到端加密。平台不自动上传完整仓库，但不能把网页预览理解为“文件内容从不离开本机”。模型工具返回的内容还会进入对应私人 AI 会话。
- 仓库 URL 和成功推送后的审核元数据对项目成员可见。推送会把该分支及其需要的历史发布到配置的远程，权限覆盖整个仓库；**不继承原本地文件 MCP 的子目录授权**。只有完全信任的独立客户端才应持有该授权，worktree 也不是安全沙箱。
- 服务端逐次验证项目、AI、主人、设备凭证与权限。任务必须分配给此 AI；`todo/in_progress` 允许获准修改/推送，`review/done` 只允许读取，重新分配或撤销批准会拒绝后续操作。本机每个操作开始时重新验证，提交和推送关键步骤前再次验证。
- 提交使用 HEAD、状态、改动文件内容和暂存差异形成版本指纹。只暂存指定相对路径；已有暂存内容时拒绝提交，防止夹带用户其他改动；授权返回后再次校验快照，提交前核对暂存 blob 与已查看内容。需要内容过滤/换行转换的文件可能被拒绝，应在本机处理。Git 命令以固定 argv、`shell:false` 执行；子进程不继承 CoNest/model token 环境变量。仓库、origin、推送目标与当前固定分支必须匹配。
- 本地常见密钥/环境配置/数据库/凭证路径、隐藏文件（`.gitignore/.gitattributes/.github` 除外）、符号链接与硬链接被阻止。这是路径过滤，**不是完整的内容秘密扫描**，不能保证任意文件或历史里没有秘密。
- Hooks、fsmonitor、外部 diff 与提交签名自动执行被禁用；仓库级 include/filter/credential/SSH 程序等配置被拒绝，系统/用户级 Git 认证仍可使用。当前版本不执行仓库脚本、依赖安装或 CI，不支持依赖本地 Git filters 的工作流，例如自动 LFS checkout。
- 同一个 Git common directory 使用操作锁；本机 runner 另有进程锁。锁不会自动抢占，异常退出留下的锁需核对对应 PID 和实际仓库状态后手动处理。此锁只协调 CoNest 进程，不能给外部编辑器、终端或本机恶意进程提供事务/OS 隔离。
- 同步只允许工作目录干净时 fetch 目标分支再 `merge --ff-only`。分叉、冲突、认证失败或远程拒绝推送都会停止，保留已有内容。
- 领取是一次性的：超时十分钟标记 `uncertain`，不自动重放 Commit / Push。网络回执重试仅重发相同 lease/result；成功回执幂等，不重复生成审核记录。撤销连接会使队列失败、已领取操作标为待核对；已经开始的 Git 子进程或已经推送的内容无法由撤销追溯取消。

## 实现位置

- `shared/git.ts`：动作/输入校验、固定分支与审核 URL。
- `server/git.ts`：仓库、工作区、权限、设备确认、队列、幂等回执、任务审核关联。
- `examples/git-repository.ts`：本地受约束 Git 操作、worktree、差异快照与锁。
- `examples/git.ts`：配对、出站 runner、独立私人 MCP。
- `src/GitPanel.tsx`：文件区的仓库接入、差异、提交、同步和审核入口。
- `tests/git.test.ts`：临时真实仓库、bare 远程、HTTP 权限及真实 runner/MCP 测试。不向用户真实仓库执行提交/推送。
